## Keputusan yang diambil user sesi ini (dan kenapa)

1. **Satu layar tanpa tab** untuk Investasi (desktop: `/investments` punya tab Ringkasan/Detail + halaman detail terpisah). Di ponsel dua tab itu duplikat. Pie distribusi dan "Per Jenis Instrumen" ditunda; badge `labels` dicabut dari kartu karena mobile belum punya sistem label.
2. **Catat Pembelian = layar penuh** (bukan bottom sheet): 7 field + keyboard numerik rawan sempit di sheet. **Toggle harga Satuan/Total ikut desktop** (yang tersimpan tetap harga per unit; mode cuma state form, dihitung di `derive-purchase.ts`).
3. **Pembelian tanpa kas (hibah, bonus, saldo/unit awal) lewat toggle "Sumber: Dari akun kas / Tanpa kas" di layar yang sama** — BEDA dari desktop yang memindahkan direct ke form transaksi utama. Alasan: tanpa itu unit yang sudah dipegang sebelum pakai app tidak bisa dicatat, dan ini yang paling mudah ditemukan. Direct = transaksi `income` di akun investasi itu sendiri (nominal boleh 0) + baris pembelian `settled`, harga per unit wajib.
4. **Edit pembelian lewat layar khusus** (ketuk baris riwayat): unit, harga (per unit/total), status Pending→Settled. Nominal, tanggal, dan hapus lewat tombol "Buka transaksi terkait". Form transaksi UTAMA tidak punya field unit/harga/status, jadi `applyInvestmentTransactionEdit` hanya menyinkronkan tanggal dan akun tujuan, dan dipanggil SEBELUM `UPDATE transactions` supaya penolakan tidak meninggalkan tulisan setengah jadi.
5. **Balance Correction akun investasi diblokir** dengan pesan penolakan (seperti debt) sampai versi koreksi unit digarap. Tipe akun terkunci permanen di layar edit akun.
6. **Update Nilai Pasar: `updated_at` selalu maju walau nilai sama** (user mengonfirmasi nilai masih berlaku, dan kolom itu penanda staleness). Form akun sebaliknya hanya memajukannya kalau `unit_label`/nilai benar-benar berubah. Tidak ada trigger di mobile — kodenya yang wajib mengisi.

## Aturan bisnis yang dipegang (jangan sampai terlanggar di Tahap B)

- **Penjualan `pending` TIDAK BOLEH membuat transaksi apa pun** — `transaction_id`, `adjustment_transaction_id`, `average_cost_per_unit`, `realized_pl` semuanya NULL sampai Settle. Dana baru cair saat settled. Form transaksi utama hanya boleh jual `settled` langsung; `pending` hanya lewat dialog khusus.
- **Saldo akun investasi dikurangi `average_cost × unit`, BUKAN nominal jual.** Satu baris transfer cuma punya satu `amount`, jadi jual = DUA transaksi: leg transfer (`average_cost × unit`) dan leg `income`/`expense` di akun kas sebesar `realized_pl` (`adjustment_transaction_id`, NULL kalau 0).
- **Dua rumus unit yang tidak boleh dicampur**: `total_unit` untuk Unrealized P/L = pembelian pending+settled; `getRemainingUnit` (basis oversell + average cost) = pembelian settled − penjualan pending+settled. Average cost = `SUM(unit×harga)/SUM(unit)` atas pembelian settled SAJA. Sudah satu sumber di `investment-holding-math.ts`.
- Modal = `accounts.balance` (on-the-fly dari transaksi). Update nilai pasar TIDAK membuat transaksi dan TIDAK mengubah saldo.
- Write-off = baris `investment_sales` dengan `price_per_unit = 0`, `status` selalu settled, satu transaksi `expense` langsung di akun investasi sebesar `average_cost × unit`, tanpa leg kas.

## Temuan / jebakan yang ketemu sesi ini

1. **`applyDebtTransaction` punya cabang terakhir "selain itu = debt→kas".** Menambah varian pasangan akun baru ke `classifyAccountPair` TANPA guard membuat transfer investasi diam-diam diproses sebagai debt. Sudah diberi guard + test regresi (`apply-debt-transaction.test.ts`). Siapa pun yang menambah varian pasangan lagi (mis. `third_party`) wajib cek cabang itu.
2. **Tanpa `detachInvestmentPurchaseForDeletedTransaction`, menghapus transaksi pembelian dari halaman Transaksi meninggalkan baris `investment_purchases` yatim** (FK `ON DELETE SET NULL`) yang unitnya masih ikut average cost — dibuktikan oleh test. Hapus di `app/transactions/[id]/edit.tsx` sekarang berjalan dalam satu `withTransactionAsync` (debt detach + investasi detach + DELETE) dan menampilkan info "Pembelian investasi ikut dihapus".
3. **Layar Edit Pembelian jadi basi setelah transaksi terkait dihapus** (tumpukan layar kembali ke baris yang sudah hilang). Diperbaiki: dimuat ulang tiap fokus lewat `useFocusEffect` dan menutup diri kalau barisnya hilang; isian form hanya diisi sekali supaya perubahan yang belum disimpan tidak ter-reset. **Sudah dikonfirmasi user berhasil di device.**
4. **Tipe route Expo (`.expo/types/router.d.ts`) rusak oleh watcher dev server** tiap ada berkas/direktori baru di `src/` (entri sampah `/../lib/...`, dan route dinamis `/investments/[id]` tercatat sebagai `/investments/[id]/index` statis). Gejala: `tsc` error `Type '"/investments/[id]"' is not assignable to ...` di `app/investments/index.tsx`. Perbaikan: restart dev server, atau regenerasi sekali jalan dengan `CI=1 timeout 50 npx expo start --port 8099 --offline` lalu `npx tsc --noEmit`. `.expo/` di-gitignore. Penyebab akar belum diselidiki.
5. **`FormFieldNumber` mode `grouped` (bilangan bulat) membuang semua non-digit**, jadi tidak bisa dipakai untuk unit/harga berdesimal — makanya prop `decimal` ditambahkan, bukan `grouped` dilonggarkan.
6. **`DebtEditBlockedError` tampaknya tidak ditangkap di UI manapun** (grep di luar `shared/debts` kosong) — pengamatan sambil lalu, BELUM diverifikasi dan di luar scope sesi ini. Cek kalau suatu saat edit transaksi debt melempar error mentah.
7. **ESLint desktop: error `Unable to resolve path to module '@/lib/db'` (`import/no-unresolved`) di `apps/desktop/src/shared/investments/investment-holding-math.ts` — DIREPRODUKSI** dengan `npx eslint <berkas>` dari root. Importnya valid (`@/lib/db` ada, alias di `apps/desktop/tsconfig.json` benar). Penyebab: satu-satunya config ESLint yang berlaku untuk desktop adalah `eslint.config.js` di ROOT (config Expo), root tidak punya `tsconfig.json`, jadi resolver TypeScript tidak tahu alias `@/*` desktop. Desktop tidak punya config ESLint sendiri (`lint` = `next lint`). **Koreksi: di tengah sesi saya sempat bilang root tidak punya `node_modules` dan karena itu tidak bisa direproduksi — itu keliru** (root punya `node_modules` lengkap dengan eslint, `eslint-config-expo`, resolver typescript). Belum diperbaiki; opsi ada di bagian Belum dikerjakan.
